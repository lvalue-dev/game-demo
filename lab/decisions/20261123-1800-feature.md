# 리그 득점·출전 집계 개편 (저장 v12)

- 사이클: `20261123-1800-feature` (기능) · 회의록 전문: https://lab.221-148-109-79.sslip.io/r/20261123-1800-feature/
- 요약: 직접 지휘한 리그 경기의 실제 득점자를 시즌 골에 반영하고, 결산 무작위 분배는 남은 골에만 적용합니다. 선수 출전 수를 새로 세서 통산 기록 기능의 저장 포맷 기반을 한 번에 마련합니다.

## 수용 기준
- 실시간 리그 경기에서 A가 2골을 넣으면 정산 직후 A의 goals +2, apps +1, season.liveGoals +2
- 골을 넣고 교체되어 나간 선수의 골과 출전이 반영되고, 교체로 들어온 선수의 apps가 1 늘어남
- m.live가 null인 리그 경기 정산 시 liveGoals는 그대로이고 선발 11명 apps만 +1
- 실시간 컵 경기 정산 시 누구의 goals와 apps도 변하지 않음
- 교체 없이 시즌 내내 선발인 선수의 apps가 그 시즌 우리 리그 경기 수와 같음
- 결산 직후 squad와 reserves 골 합이 row.gf 이하
- 결산 뒤 reserves의 goals와 apps가 0
- v11 저장을 불러오면 version 12가 되고 apps와 liveGoals가 0
- 타입 검사, 전체 테스트, 빌드 통과, 봇 시뮬레이션 승률과 순위 분포가 전후 동일

## 채택하지 않은 안
- 안 A 기자회견: events.ts의 derby, referee, protest 사건과 선택지가 거의 같아 새 선택이 생기지 않음
- 안 C 상대 분석 카드: match.ts의 경기 전 분석 문장과 styleChoices 상성 표시, readChance 흐림이 이미 있고, 새로 생기는 '위험 선수 한 명'만으로는 선택이 바뀌지 않음
- 판매 시 기록 소멸 경고: 화면 요소가 추가되고 통산 기록 이후에 의미가 커지므로 미룸

## 남은 이견
아이디어 담당은 시즌 중 판매·임대로 기록이 사라질 때 경고를 띄워야 한다고 봅니다. PM은 통산 기록이 생기기 전에는 잃는 값이 시즌 한정이라 보고 문서에만 적고 미뤘습니다.

## 리뷰 결과
- 사이드 이펙트: 새 코드는 난수를 쓰지 않고 shareGoals 인자만 바뀌며 봇은 live를 쓰지 않아 liveGoals가 0이므로 봇 수치가 그대로인 것이 명세와 일치한다. 저장은 v12로 올라가고 migrate가 apps, liveGoals를 채우며 gone은 선택 필드라 v11 경기 도중 저장도 정산된다.
- 중복: 출전·득점 집계를 하는 기존 함수나 상수는 찾지 못했다. L.gone은 기존 L.subbed(이름 목록)와 용도가 달라 중복이 아니다.
- PM 중재: 없음(리뷰어 승인)
- 막지 않은 제안:
  - career.ts startHalf: 자동 경기 출전 증가에 !club.nation 가드를 명시(대표팀에서 playRound line이 항상 null인지 미확인)
  - 컵 경기 테스트는 끝난 리그 경기의 kind/ko를 바꿔 정산하므로 실제 컵 경로의 검증은 아님
  - pid ?? -1 센티널이 swapIn과 countLeagueMatch 두 곳에 있음. 나중에 pid 타입 정리 때 통합
  - 선수 골은 기록 그대로 더하고 liveGoals만 스코어로 자르므로, 기록이 스코어를 넘으면 골 합 ≤ row.gf 불변식이 깨질 수 있음(정상 경기에서는 발생하지 않는 것으로 보임, 미확인)
