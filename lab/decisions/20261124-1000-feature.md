# 라이벌전 승리 공언: 이사회 신뢰에 판돈 걸기

- 사이클: `20261124-1000-feature` (기능) · 회의록 전문: https://lab.221-148-109-79.sslip.io/r/20261124-1000-feature/
- 요약: 클럽 라이벌 리그전 직전에 '승리를 공언한다(+5/−1/−5)'와 '말을 아낀다(±2)' 가운데 하나를 고르게 한다. 방금 쌓은 라이벌 전적을 실제 선택으로 잇되, 경기력과 균형 수치는 건드리지 않고 신뢰 변화량만 바꾼다.

## 수용 기준
- 클럽 라이벌 리그전은 beginMatch 직후 match.step === 'vow'이고, 컵·대표팀·비라이벌 경기는 'shape'로 시작한다
- vow 단계의 첫 선택지 id는 'quiet', 둘째는 'vow'이며, 어느 쪽을 골라도 step이 'shape'로 넘어가고 m.vow가 기록된다
- rivalTrustDelta(true, …)는 승 +5·무 −1·패 −5, rivalTrustDelta(false, …)는 +2·0·−2를 돌려준다
- 공언한 뒤 'auto'(수석 코치)로 끝낸 라이벌전도 settle 후 job.confidence 변화가 rivalTrustDelta(true, gf, ga)와 같다(0~100으로 자른 값)
- vow 필드가 없는 MatchState로 정산하면 ±2 규칙이 적용된다
- vow 단계에서 저장한 게임을 JSON 왕복 후 불러와도 step이 'vow'이고 선택지 둘이 같다
- 신뢰가 27 미만이면 'vow' 선택지 설명에 '경질 위험'이 포함되고, 27 이상이면 포함되지 않는다
- 기존 rivalSweepBonus 테스트, 순위표 경기 수 테스트, 전체 테스트, 타입 검사, 빌드가 통과한다
- 봇 시뮬레이션 전후 비교에서 지표 차이가 없다

## 채택하지 않은 안
- 선수 폼 시스템: 자동 경기에 선수별 평점이 없어 입력이 추정값이 되고, ratingsNow·봇 균형·저장 v13을 한꺼번에 건드려 한 사이클을 넘는다
- 더비 올인/실리를 경기력·체력 보정으로 구현: PLANS의 allout/steady와 이름과 기능이 겹치고, 경기 사이로 이어지는 체력이 없으며, 전력 계산과 봇 수치를 흔든다
- 시즌 결산 한 줄 요약 + 막힌 후보 숨기기: 새 선택이 없고, 토글은 별도의 작은 사용성 작업이다
- 승률 구간별 기대값 표를 수용 기준에 넣는 안: 차이는 승 +3·무 −1·패 −3이라 승률과 패률이 같으면 공언이 손해다. 판단이 갈리도록 의도한 설계이고, 단위 테스트는 rivalTrustDelta 값 검증으로 충분하다

## 남은 이견
아이디어 측은 공언 후 수석 코치 위임을 막아야 한다고 봤으나, 직접 지휘와 위임을 같게 센다는 기존 원칙(RULES.md 140행)에 따라 막지 않는다. 무승부 −1의 손익 균형은 봇 시뮬레이션에서 공언을 고르지 않으므로 이번에 검증되지 않는다.

## 리뷰 결과
- 사이드 이펙트: beginMatch의 step 초깃값과 actMatch shape 분기의 id 가드만 기존 흐름에 닿는다. 난수 소비 순서, 저장 형식(vow? 선택 필드), 봇 수치는 변하지 않는다. UI 호출 경로는 모두 유효한 대형 id만 보낸다.
- 중복: 새로 만든 중복 함수는 없다(attach는 josa.ts, SHAPE_IDS는 tactics.ts의 기존 것을 씀). 다만 설명 문자열에 신뢰 변화 숫자가 하드코딩되어 rivalTrustDelta와 이중 관리된다.
- PM 중재: 없음(리뷰어 승인)
- 막지 않은 제안:
  - style.css: 제목 클래스(292행 부근)의 word-break: keep-all에 overflow-wrap: break-word를 함께 두거나 이 변경을 따로 분리한다(명세 밖 변경, 긴 이름 넘침 위험)
  - match.ts scene의 +2/−2, +5/−1/−5 설명 문자열이 career.ts rivalTrustDelta의 숫자와 중복이다. 순환 참조만 아니라면 한 곳에서 만들도록 나중에 정리한다
  - 정산 경계 테스트는 score를 덮어쓰므로 done 장면 note는 검증하지 않는다는 점을 주석으로 남긴다
