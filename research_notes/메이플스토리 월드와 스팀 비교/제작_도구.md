## 1. 에디터 이름, 지원 OS, 무료 여부

### Takeaway
제작 도구의 이름은 "메이플스토리 월드 메이커(Maker)"이며 PC용 메이플스토리 월드 앱 안에서 "만들기와 플레이"를 함께 제공하는 구조로 요약된다. Windows 사양표는 공식 다운로드 페이지에서 확인되지만, **메이커가 macOS에서 동작하는지와 "무료"라는 명시 문구는 이번 조사에서 확인하지 못했다.**

### Inferences
- 위 사양표는 "메이플스토리 월드" 앱(플레이+제작 통합) 기준이며, 메이커 전용 사양표는 발견되지 않았다. PC 앱이 제작을 겸한다는 요약이 맞다면 메이커 사양도 같은 표를 따를 가능성이 높다(추정).
- Mac 사양이 공식 지원 문서에 있는 것은 "플레이 클라이언트"의 Mac 지원을 시사하지만, **메이커(제작 모드)의 Mac 지원 여부는 별개 문제**로 확인되지 않았다. Mac 사용자는 착수 전에 반드시 공식 다운로드 페이지에서 확인해야 한다.
- 로컬 워크스페이스 + VS Code 확장 + 디버거가 존재한다는 점은, 전문 개발자가 익숙한 "텍스트 파일 편집 → 외부 에디터 → Git" 흐름을 어느 정도 쓸 수 있음을 시사한다(세부 워크플로는 원문 미확인).

### Gaps
- 메이커가 **무료**인지에 대한 명시적 문구는 검색 결과에서 확인하지 못했다(유료라는 언급도 전혀 없음. 넥슨 계정으로 받아 쓰는 무료 도구로 널리 알려져 있으나 이번 조사에서 출처를 확보하지 못함).
- 메이커의 macOS 지원 여부, 메이커 최신 버전 번호, 설치 경로(넥슨 런처 여부)는 미확인.
- 엔진이 Unity 기반이라는 점은 나무위키 요약뿐이며 공식 출처 미확보.

## 2. 스크립트 언어(mLua), 일반 Lua와의 차이, 엔티티/컴포넌트 모델, 네트워킹 모델

### Takeaway
스크립트 언어는 Lua 5.3 기반의 "mLua"(.mlua 파일)이며, 프로퍼티·메서드에 타입을 선언하고 `@Component`, `@Logic`, `@ExecSpace`, `@Sync` 같은 어노테이션으로 실행 공간(서버/클라이언트)과 동기화를 지정하는 확장 문법을 쓴다. 구조는 엔티티에 컴포넌트를 붙이는 방식이고 서버·클라이언트 실행 공간을 구분하는 모델이지만, "서버 권위(server-authoritative)"라는 명시적 문구와 플랫폼 공통 최대 인원 수치는 확인하지 못했다.

### Cited Findings
- (검색 요약 기준, 원문 미확인) [공식] API 레퍼런스 안내에 "mLua는 Lua 5.3과 사소한 차이(minor differences)가 있다"고 기술. 차이 목록은 요약에 없음 — [API Reference Guidelines](https://maplestoryworlds-creators.nexon.com/en/apiReference)
- (검색 요약 기준, 원문 미확인) [공식] 표준 Lua의 `print` 대신 `log()` 함수를 사용. 배열 인덱스는 Lua 일반 규칙대로 1부터 시작 — [MapleStory Worlds Lua Basics](https://maplestoryworlds-creators.nexon.com/en/docs?postId=822)
- (검색 요약 기준, 원문 미확인) [공식] 확장 스크립트 포맷: 스크립트 헤더에 스크립트 종류와 상속 대상을 명시. 프로퍼티는 "타입 + 이름 + (선택) 기본값"으로, 메서드는 "반환 타입 + 이름 + 타입이 지정된 매개변수"로 선언. 이벤트 핸들러에는 EventSender 속성 필요 — [ExtendedScriptFormat](https://maplestoryworlds-creators.nexon.com/en/docs?postId=1166)
- (검색 요약 기준, 원문 미확인) [공식] 제작 가이드 목차에 "어노테이션 활용", "프로퍼티 동기화", "함수", "MSW 기본 이벤트 함수", "엔티티와 컴포넌트 참조", "서버와 클라이언트", "실행 공간 제어(Execution Space Control)", "MSW Lua 기초", "MSW Lua 문법 확장 가이드" 항목이 있음 — [Creation Guide (postId=210)](https://maplestoryworlds-creators.nexon.com/docs?postId=210), [postId=205](https://maplestoryworlds-creators.nexon.com/docs?postId=205)
- (검색 요약 기준, 원문 미확인) [제3자 목록 — msw-git "official" 명칭의 AI 코딩 플러그인 설명] .mlua 작성 스킬이 `@Component`, `@Logic`, `@ExecSpace`, `@Sync` 어노테이션, 라이프사이클 훅, 실행 공간, 프로퍼티 동기화, 이벤트 시스템을 다룸 — [skills.sh: msw-scripting](https://skills.sh/msw-git/msw-ai-coding-plugins-official/msw-scripting)
- (검색 요약 기준, 원문 미확인) [제3자 목록] UI 엔티티는 클라이언트에만 존재하므로 서버 코드에서 참조하면 nil. 서버→UI 통신은 `@ExecSpace("Client")` RPC를 거쳐야 함. 서버 전용 메서드는 `@ExecSpace("ServerOnly")`로 명시 — [skillselion: msw-scripting](https://skillselion.com/skills/msw-git/msw-ai-coding-plugins-official/msw-scripting)

- (검색 요약 기준, 원문 미확인) [공식] 인스턴스 맵(인스턴스 룸) 문서: 서버 측 Lua 코드로 일정 인원이 준비되면 플레이어를 새 인스턴스 룸으로 이동시키는 예시 — [Creating Instance Map](https://maplestoryworlds-creators.nexon.com/en/docs?postId=540)
- (검색 요약 기준, 원문 미확인) 개별 월드의 인원 예시(플랫폼 규칙이 아니라 월드별 설정 값): 샘플 월드 페이지에 "Max Players 16", NexTale은 "인스턴스당 20채널, 최대 75명", BROA는 월드 인스턴스 최대 30명 — [샘플 월드 페이지](https://maplestoryworlds.nexon.com/en/play/c2c13b1763e549798db8639b662240f6), [NexTale 월드 페이지](https://maplestoryworlds.nexon.com/en/play/c0e7a040a3ce457a9eda29877c986871/), [제3자 가이드(ExitLag)](https://www.exitlag.com/blog/maplestory-project-maple/)
- (검색 요약 기준, 원문 미확인) [커뮤니티] 대형 월드 Mapleland는 채널당 1000명으로 출시했으나 300명만 넘어도 렉으로 원활한 플레이가 어려워 최대 인원을 300명으로 낮춤 — [나무위키: Mapleland/문제점](https://namu.wiki/w/Mapleland/%EB%AC%B8%EC%A0%9C%EC%A0%90)

### Inferences
- Java/Python/JS 개발자 관점에서 mLua는 "Lua 문법 + 타입 선언이 붙은 프로퍼티/메서드 + 데코레이터 유사 어노테이션" 조합이다. 엔티티에 컴포넌트를 붙이고 라이프사이클 훅(OnBeginPlay 계열로 추정, 정확한 이름은 원문 미확인)을 구현하는 방식은 Unity의 GameObject/MonoBehaviour와 개념적으로 유사하다.
- `@ExecSpace("ServerOnly")`/`("Client")` RPC, `@Sync` 프로퍼티 동기화, 서버 전용 DataStorage가 있다는 점에서 **서버가 상태를 보유하고 클라이언트로 동기화하는 서버-클라이언트 구조**(넥슨이 서버를 호스팅)로 보인다. 다만 "server-authoritative"라는 공식 표현은 확인하지 못했으므로 추정으로만 취급할 것.
- 인원 수치 사례(16, 30, 75, 300, 1000)는 모두 월드별 설정이며, Mapleland 사례는 "설정 가능한 상한"과 "실제로 쾌적한 인원" 사이에 차이가 있음을 시사한다.

### Gaps
- mLua와 Lua 5.3의 차이를 열거한 공식 목록은 확인하지 못함(검색 요약은 "사소한 차이"라는 문장만 제공).
- 플랫폼 공통의 인스턴스당 최대 인원 상한, 서버 틱레이트, 서버 사양, 서버 권위 여부에 대한 공식 문구는 찾지 못함.
- msw-git/msw-ai-coding-plugins-official 저장소가 실제 넥슨 공식 저장소인지 직접 확인하지 못함(저장소명에 "official"이 있고 공식 로드맵의 AI 지원 방향과 부합하지만, 깃허브 접근 불가로 미검증). Hugging Face의 msw-ai-tf 계정도 공식 여부 미검증.

## 3. 제공 에셋, 자체 리소스 업로드, 2D 한정 여부, 실시간 액션/슈팅 가능성과 한계

### Takeaway
메이플스토리 IP 리소스(애니메이션이 내장된 몬스터·스킬 이펙트 포함)가 기본 제공되고, 크리에이터는 스프라이트·애니메이션 클립·오디오 클립·아바타 아이템을 직접 등록할 수 있다. 등록 가능한 리소스 유형에 3D 모델이 없으므로 2D 플랫폼으로 보이며, 물리는 기본 꺼져 있고 PhysicsSimulatorComponent를 추가해야 적용된다. 틱레이트 등 실시간 액션 성능 수치는 확인되지 않았다.

### Cited Findings

### Inferences
- 성능 병목은 주로 "한 인스턴스에 수백 명이 몰리는 MMO형 월드"에서 보고된 것이므로, 소규모 인원(수~수십 명) 미니게임을 만드는 솔로 개발자에게는 당장의 제약이 아닐 가능성이 높다.
- 플랫폼(넥슨)이 엔진·서버를 일괄 운영하므로, 플랫폼 업데이트가 내 월드를 깨뜨릴 수 있고 그 일정을 크리에이터가 통제할 수 없다는 점이 구조적 리스크다(Mapleland 사례에서 유추).
- 독자 언어(mLua)와 독자 엔진 API이므로 학습한 내용의 외부 이식성이 낮고, 스택오버플로·범용 AI 같은 일반 개발 자원의 도움을 받기 어렵다. 2026년의 전용 AI 도구들이 이 약점을 메우려는 시도다.

- 메이커 에디터의 크래시·저장 유실·협업(동시 편집)·버전 관리 관련 2026년 시점 불만은 수집하지 못함(공식 포럼·디시 갤러리 원문 접근 불가).
- 디버깅 도구(브레이크포인트, 서버 로그 조회, 프로파일러)의 실제 사용성 평가를 찾지 못함. mLua 디버거 가이드가 존재한다는 것만 확인.
- 데이터 저장소(DataStorage)의 호출 한도·용량 제한, 플레이테스트 시 서버/클라이언트 동시 실행 방식 등 세부 제약 미확인.
